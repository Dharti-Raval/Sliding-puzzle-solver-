# Optimal Sliding Puzzle Solver

A Flask web app that finds the **minimum-move solution** for the 8-puzzle (3×3)
and 15-puzzle (4×4) sliding puzzles.

## Features
- Enter any board, or generate a random **guaranteed-solvable** puzzle.
- Solvability check via the **inversion-count rule**.
- Optimal solver:
  - **A\*** + Manhattan Distance for 3×3.
  - **IDA\*** + Manhattan Distance for 4×4 (low memory, still optimal).
- Shows: solvable/unsolvable, algorithm used, minimum move count, full move
  sequence, every intermediate board state, and a step-by-step animation.

## Algorithm Explanation

**State space:** each board is a permutation of `0..N²-1` (0 = blank tile).
Each state has up to 4 neighbors, generated by sliding a tile adjacent to
the blank into the blank spot.

**Heuristic — Manhattan Distance:**
`h(n) = Σ |current_row - goal_row| + |current_col - goal_col|` over all
tiles except the blank. This heuristic never overestimates the true
distance (admissible) and never decreases by more than 1 per move
(consistent) — both required for A*/IDA* to guarantee optimality.

**A\* (3×3):** classic best-first search with `f(n) = g(n) + h(n)`, using a
min-heap (`heapq`) ordered by `f`. Because `h` is consistent, the first time
the goal is popped from the heap, `g(goal)` is the optimal move count.
Memory use is fine for the 8-puzzle (state space ≈ 181,440 reachable states).

**IDA\* (4×4):** the 15-puzzle's state space (~10 trillion states) is too
large for A*'s memory. IDA* instead repeats a depth-first search with an
increasing `f`-value cutoff (`bound`), starting at `h(start)`. Any branch
whose `f = g + h` exceeds the current bound is pruned; if the goal isn't
found, the bound is raised to the smallest `f` that was pruned, and the
search restarts. This uses only O(solution depth) memory while still
guaranteeing the optimal solution, because it never expands a node whose
`f` exceeds the true optimal cost.

**Solvability (inversion rule):** count inversions in the tile sequence
(pairs `(a, b)` where `a` appears before `b` but `a > b`, blank ignored).
- **3×3 (odd width):** solvable iff inversions is **even**.
- **4×4 (even width):** solvable iff `inversions + (blank's row counted
  from the bottom, 1-indexed)` is **odd**.

**Random puzzle generation:** start from the goal state and apply a
sequence of random *legal* moves (avoiding immediately undoing the previous
move). Since every move is reversible, the result is always solvable —
no need to check afterward.

## Viva — Short Explanation
> "The board is a permutation of tiles with one blank. We first check
> solvability using the inversion-count parity rule — this avoids wasting
> time searching for solutions that don't exist. If solvable, we search
> the state space using A* (3×3) or IDA* (4×4), guided by the Manhattan
> distance heuristic, which estimates how many moves each tile is from its
> goal position. Because this heuristic never overestimates the true cost,
> both algorithms are guaranteed to return the *minimum* number of moves.
> IDA* is used for 4×4 instead of A* because it explores the same states
> depth-first with an increasing cost bound, needing far less memory than
> A*'s open/closed lists — essential since the 15-puzzle has ~10¹³ states."
